# Chst

Chst is a new, versioned container file format (`.chst`) with a Rust library and CLI, designed and built with a coding agent under a spec-first, evidence-based workflow.

## Status

The specification, 167 test fixtures, six review rounds and the acceptance harness are complete, and CI runs on Linux, macOS and Windows.

**The Rust implementation has not started. Nothing here is usable as a tool yet.** Most acceptance checks report FAIL for that reason, and `EVIDENCE.md` records that honestly: on Linux, 10 of 85 criteria pass (they check only the fixtures, the documents and the harness), 53 fail, 3 are not run in fast mode, and 19 are N/A. Its macOS and Windows columns are not yet filled in from CI.

## What it is

A container for bundling a directory tree into one file, then listing, verifying and extracting it. The goals, from `DESIGN.md`:

- **A language-neutral spec.** `FORMAT_SPEC.md` is normative, and it wins over the code if they disagree.
- **Safe extraction.** Extraction goes only into a new destination, through a private staging directory, and refuses hostile paths.
- **SHA-256 integrity.** Every blob has a content hash, and a structure hash covers the header, index and trailer.
- **Versioning.** One wire format, with a Core v1 cut to build first and an Extended v1 cut of optional features after it.

The planned CLI is `chst pack`, `list`, `inspect`, `verify` and `extract`.

## How it's built

1. **Plan first.** Every design decision is in the decision log in `DESIGN.md`.
2. **Write the spec.** `FORMAT_SPEC.md` has the byte layout, rules and error model.
3. **Define done before coding.** `ACCEPTANCE.md` has 85 criteria, each with an exact check command.
4. **An independent test oracle.** `fixtures/` is generated by a standard-library-only Python program in `fixtures/gen/`, built to share no code with the Rust implementation (AC-META-4 checks this).
5. **Independent review.** `reviews/` holds six records: four full reviews, then two narrow checks of the changes. The first two reviewers each wrote their own reader from the spec alone before opening the generator; the third and fourth updated that reader.
6. **Evidence.** `check.sh` runs the criteria, and `EVIDENCE.md` records one row per criterion.

## Running the checks

You need `bash`, `jq` 1.7 or later, and `python3.14` (with `compression.zstd`) on your `PATH`. Run from the repository root, on a Linux filesystem if you're in WSL.

```sh
./check.sh                       # fast mode: every applicable criterion
./check.sh --full                # also the full-only criteria (fuzzing, large files)
./check.sh --only AC-META-1,AC-META-2   # just those criteria
./check.sh --list-ids            # the criteria IDs
```

Each criterion reports PASS, FAIL, NOT RUN or N/A. The exit code is 1 if anything failed, 2 if nothing failed but something was not run, and 0 otherwise. The report is `target/acceptance/report.json`, with one log per criterion in `target/acceptance/logs/`.
